# M1 两层容量筛选 v3

32K=32512、16K=16384，沿用同一 v3 根会话、seed=0、锚点和间隔；本次只做 CPU 分析。

## 新约束和估算口径

容量筛选严格执行 `2.5×运行中 KV P90 ≤ GPU池 < CPU层 ≤ 0.8×工作集`，且 `1.5≤CPU/GPU≤2`；取消 GPU+CPU<工作集。GPU 最小池向上取整到 16 token，CPU/GPU 目标为 1.5/1.75/2，并向上取整到 block。GPU/CPU 独立保留副本，因此不能把两层容量相加理解为可用工作集。

**P90 定容口径保持保守：** 每个槽位从全部请求混合等权抽样完整 prompt+输出、独立求和，20000 次固定种子；取其 P90 与固定 s=0.5 有限槽位模拟 P90 的较大值。表中列出这两者。没有把低并发 s=0.5 占用当成满槽位占用。

**工作集方法（以下每组相同）：** 用固定 s=0.5 的无缓存反馈估算调度和同一 M/G/∞ 稳态人口；对每条尚未结束的链取最近已发送的 prompt，计算同实例不同 prompt 的前缀 trie 并集 token 数。实例之间不共享，链最后一次请求完成后移除；不包含输出 KV。40 分钟窗口、前 10 分钟预热，统计段每 10 秒采样；用 P50 作上述 0.8 倍约束，另报 P90。这是活跃上下文 footprint 口径，不是实测复用距离工作集；缓存模拟中的有限槽位排队不反向修改此估计。

Qwen3-8B BF16 每 token KV=147456 bytes。主机 MemAvailable=242.20GiB；通过容量筛选的 CPU KV 最大 161.71GiB，在可用量 85% 以内。此为 KV 本体，进程和搬运缓冲区仍需试跑核验。
